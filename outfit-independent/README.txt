穿搭魔镜：本地独立版 1.3.0

双击上一级目录的“启动独立版.cmd”，打开 http://127.0.0.1:8090/ 。
需要 Node.js 24 或更新版本。本机已具备运行环境和衣物识别依赖。
在其他电脑部署时需安装 package.json 的依赖，并运行 node scripts/setup-garment-model.cjs 下载模型。
启动器默认允许同一 Wi-Fi 的手机访问；终端会打印当前局域网地址。
这是本地 HTTP 服务：请在可信 Wi-Fi 下使用，不要将此端口直接暴露到互联网。

照片自动录入（1.3.0 新增）：
在“我的衣橱”点“添加单品”，直接拍照或从相册选图；系统自动建议名称、类别、主色和季节，同时尝试制作白底单品图。
确认预览后点“保存到衣橱”，无需逐项手填。手动修改、编辑已有记录时的信息会优先保留；点击“按照片重新填写”可按本次照片重新建议。
识别在本机完成，不发送照片至外部 AI，也不需要配置付费图像 API。
此电脑的模型已准备；其他电脑需分别运行 node scripts/setup-garment-model.cjs 和 node scripts/setup-item-recognizer.cjs 下载公开模型。
轮廓使用 SegFormer，款式使用固定版本的本地 CLIP；颜色只从识别的衣物区域提取，季节按可见款式估计，不判断真实材质、品牌或实际保暖程度。
遇到遮挡、多件衣物、识别不确定或模型未准备时会提示检查；单品图失败也会保留原图与可用的自动填写结果。
本机季节建议可直接修改；换照片、关闭编辑或切换账号后，旧识别结果不能回填到新照片或其他账号。

自己滑着搭（1.2.0 新增）：
在“今日搭配”选择“自己滑着搭”，上装、下装和鞋子从上到下排列。
每行都可以独立左右滑动，居中的单品即为当前选择；电脑可使用两侧箭头，聚焦一行后也可按左右方向键。
候选来自当前账号的衣橱，上装行含上装与外套；某类为空时可直接点击添加对应类别。
点击“查看这套搭配”后可收藏、导出整套参考图，或继续滑动调整。重新编辑收藏时恢复该套仍在衣橱中的选择。
温度与季节可直接修改；后台只提示不适温问题，不擅自替换手选单品，不调用文字 AI。
本功能展示单品组合，自动本人人像仍使用单独的图像服务配置。

首次使用：选择“注册新账号”，设置自己的账号和至少 10 位的密码。
本地账号是新账号，不会沿用原网站的验证码登录。个人档案中可修改密码；忘记密码时可在这台电脑的交互终端运行 node scripts/reset-local-password.cjs，重设前自动备份，并使该账号退出所有设备。当前没有邮箱验证或邮件找回功能。
登录状态用 HttpOnly Cookie 保存；服务器只保存加盐密码哈希和会话令牌哈希。
每次查询、修改、下载图片都验证当前账号；不同账号的数据相互隔离。
退出、账号切换和会话失效会立即清空人像、档案、衣橱、收藏和待上传图片，释放本地图片 URL，并取消旧请求。
图片导出、上传、识别和生图等异步任务绑定本次登录；切换后即使旧任务完成，也不能显示或写入新账号。
多标签页会同步账号变化，旧标签页回到登录页；请求还带预期账号标识，后台拒绝账号已变化的读写或退出操作。
收藏和档案中引用的私有图片路径必须属于当前账号；备份导入先校验全部图片再写入。新账号没有本人人像时保持空状态。
人物照片、衣服照片、档案、衣橱和收藏存入 data/outfit.sqlite，不依赖原云服务。
规则搭配、本机衣物分割、造型海报可直接使用。手机系统可能自行决定相机/图库的选择方式。
衣物处理：选择类别后上传，服务器用本地 SegFormer 衣物分割模型排除头发、人脸、肢体和背景，
裁切衣物主体并输出居中 1080×1080 白底单品图。确认预览后保存，处理图和原图一并留存。
模型识别不可靠时保留原图并提示失败，不使用旧的颜色擦除算法伪造成功。
该方式提取可见衣物，不会还原被手、包袋等挡住的细节，也不会把穿着姿势重绘成平铺形态。
建议优先上传单件平铺、悬挂或人物遮挡少的照片；改变类别可重新处理。
模型来源：https://huggingface.co/Xenova/segformer_b2_clothes
上游原模型：https://huggingface.co/mattmdjaga/segformer_b2_clothes
模型版本固定 cb6ac44e641faa309f29561c1afe08d87ef52631；推理仅在本机，不向模型网站发送照片。

数据迁移与备份：
1. 原网站和原数据保持原样，本目录没有删除或修改它们。
2. 当前尚未取得旧平台数据库及原图导出，所以尚未导入旧数据。
3. 新版“个人档案”提供完整备份导出（JSON，含照片），请离线妥善保管。
4. 将备份导入一个空账号，避免覆盖已有资料。导入在事务内完成，失败则回滚。
5. 旧平台导出的 profiles.json、wardrobe_items.json、outfits.json 及照片目录
   可用 scripts/prepare-import.cjs 转为相同备份格式，保留收藏与衣橱的关联。
   转换脚本不会向旧平台发请求，也不包含旧平台的密码、令牌或分享凭证。
6. 旧账号密码和登录会话不迁移；本地注册后导入数据。
7. 多账号导出应按每个 owner_id 分开；转换脚本拒绝混合账号。
8. 大于 64MB 的完整备份需拆分或在后续迁移时使用服务器侧批量工具。

可选 AI API：
复制 .env.example 为 .env，填写 LLM_API_BASE、LLM_API_KEY、LLM_MODEL，重启服务。
密钥只保存在服务器环境中，不会写入网页、数据备份或发送到浏览器。
未配置时明确使用内置规则，不会声称已连接 AI。
用户点击 AI 生成时会向所配置的服务发送档案文字和衣橱描述；当前不发送照片。

本人全身穿搭图（与文字 AI 分开配置）：
页面优先展示面部参考、身材资料和衣橱服装结合生成的人像全身图，单品拼图折叠为辅助参考。
这类图为视觉参考，不能保证面部、身材比例、服装细节或真实合身程度完全准确。
默认审美定位为 20–30 岁、清爽自然的日常穿搭，避免默认套用成熟商务造型。
已有衣服与未购买的推荐款都会在完整人像图中展示；没有衣服实拍、甚至空衣橱，也可只用面部参考和款式描述生成。
已有且有照片的款式按原图参考；已有但无照片的按名称、类别、颜色生成；未拥有的按推荐方案生成并标注待购。
推荐款图为生成的款式参考，不对应已验证的真实商品、库存或购买链接。
已保存的人像图片仅按其所属账号读取；其他账号不会继承示例图，没有本人人像时显示空状态。
App 每次自动生图需要独立配置 IMAGE_API_KEY（或 OPENAI_API_KEY）、IMAGE_MODEL 和 IMAGE_API_URL。
服务接口采用支持多张参考图的 Images Edit 格式，默认模型为 gpt-image-2，密钥只保存在服务器。
未配置时，按钮明确显示自动服务未就绪，已有图片仍可查看，不会拿拼图冒充本人人像。
每次调用需明确勾选资料使用确认：面部参考照片、身高体重身形、本套衣服参考图会发送至配置的图像服务。
生成成功会自动保存到搭配收藏；用户与其他账号的图片和资料在服务器端隔离。

季节与温度搭配：
已查看「穿搭参考图片」的 17 张拼图，并将复古学院、甜酷、清爽衬衫的配色、领型和版型整理到 public/style-guide.js；详细逐图观察位于 outputs/style-analysis-v1.json。这是规则和提示词更新，不是模型训练。
新增「参考图风格」并设为默认；原图仅作风格灵感，可在搭配结果中展开查看，服装厚度与露肤程度按温度调整。
季节切换的示例温度：春18°C、夏30°C、秋18°C、冬5°C；不是当地天气预报，用户可以修改实际温度。
温度分档：≤5°C保暖三层，6–11°C保暖外搭，12–17°C长袖与可脱外搭，18–23°C温和轻装，24–28°C轻薄透气，≥29°C清凉少叠穿。
实际温度优先于季节名称。自动筛除高温羽绒、低温夏季薄款、雨雪天帆布或麂皮鞋；不适温的预选单品显示说明并替换，低温裙装补腿部保暖。
规则搭配与文字 AI 都使用温度约束；明显冲突的 AI 输出会按本地规则重新组织。图像 API 提示词也已同步参考风格和季节温度要求，但仍需独立配置才能自动生图。

淘宝补购推荐：
每件待购单品可直接点击“去淘宝搜索这款”，按完整款式关键词打开淘宝搜索，无需申请应用凭证。搜索结果由淘宝提供，这个入口不是某件商品的详情链接。
如需自动展示真实商品卡，可选淘宝连接页：http://127.0.0.1:8090/taobao-connect.html 。
普通淘宝购物账号不能直接替代应用接口凭证；按淘宝联盟官方要求完成入驻、媒体备案、创建应用并取得商品搜索权限后，才能自动获取真实商品。
连接页提供官方入口、当前本机配置检查和真实商品查询验证；未配置时测试按钮禁用，不生成虚构商品结果。
官方接入指南：https://developer.alibaba.com/docs/doc.htm?articleId=118970&docType=1&treeId=713
文字补购推荐旁会直接展示对应的单品参考图，不依赖淘宝接口；已加入米白圆领针织上衣、浅蓝高腰直筒牛仔裤、白色运动鞋、浅灰腋下包四种 AI 图片参考。
图片点击可放大，整套参考板及其导出也使用相同图片。款式与颜色不匹配时不会强行套用这四张图，其余款式仍使用原有的轮廓示意。
参考图标注 AI 生成，非真实商品；后续若要任意新款式自动生成专属图片，还需要配置图像 API。
缺少的单品会按本套款式关键词查询淘宝，每件最多展示 3 个候选，包含商品主图、名称、店铺、售价和商品推广链接。
商品卡的图片与链接来自同一条官方商品记录；没有图片或有效商品链接的记录不展示。不会把搜索页或生成的示意图当成真实商品。
使用淘宝联盟 TOP 物料搜索升级版 taobao.tbk.dg.material.optional.upgrade，需应用具有对应 API 权限。
在本机 .env 中配置 TAOBAO_APP_KEY、TAOBAO_APP_SECRET、TAOBAO_ADZONE_ID（推广位最后一段数字），重启服务。
密钥不发送到浏览器或备份。查询只发送单品关键词，不发送面部照片、档案或衣橱图片。
官方文档：https://developer.alibaba.com/docs/api.htm?apiId=64759
尚未配置凭证时会明确显示商品源尚未配置，无法提供真实商品推荐。接口测试用合成商品验证，不能代替真实授权联调。
展示接口返回的普通售价，不推算优惠券或凑单价；商品页可能需要登录淘宝，价格、颜色尺码与库存以店铺为准。
收藏不缓存商品价格或购买链接；重新查看搭配时重新查询。人像效果图仍是视觉参考，与候选商品可能存在差异。

未来线上部署：
本版本可部署到支持 Node.js 24 和持久磁盘的服务器。
先配置 HTTPS 反向代理，APP_HOSTS 填入实际域名，COOKIE_SECURE=1，再切换域名。
不要直接把 SQLite 服务放在无持久磁盘的临时运行环境，不要公开 data/ 或 .env。
当前没有部署到线上，原来的线上网址仍是旧平台版本。
